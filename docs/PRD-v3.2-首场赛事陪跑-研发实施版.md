# 首场赛事陪跑 PRD v3.2

## 1. 文档信息

- 文档名称：首场赛事陪跑 PRD v3.2（研发实施版）
- 更新时间：2026-04-11
- 文档定位：在 v3.1 精简版基础上，进一步落到研发实施层
- 核心目标：围绕「首场赛事陪跑」做 Runna 优先级最高的对标复刻，并结合中国市场与微信小程序约束完成本地化实现
- 使用对象：产品、设计、前端、后端、算法、AI、测试

## 2. 实施总原则

### 2.1 对标原则

我们的第一对标产品不是泛泛的“跑步 App”，而是：

> Runna

其余对标产品作为局部增强参考：

1. Runna：页面逻辑、日历、动态重排、配速自适应
2. Trenara：RPE、7 天滚动调整、训练后反馈
3. Coopah：每日方向、解释层、激励语气
4. TrainingPeaks：训练负荷量化和趋势表达

### 2.2 研发原则

研发必须优先遵循下面 4 条规则：

1. 能直接复用成熟开源项目的，优先复用或二次开发
2. 没有成熟开源实现的，优先按 Runna 的页面逻辑和交互去复刻
3. 复刻的是能力、结构、逻辑和信息架构，不是品牌、视觉素材和版权文案
4. 所有实现都必须适配中国市场和微信小程序使用习惯

### 2.3 平台原则

由于我们不是记录型运动 App，所以平台实现必须收敛：

1. 不做 GPS 实时记录
2. 不做训练中实时语音
3. 不做卡路里和运动消耗
4. 不做复杂设备接入
5. 不做社区和赛事平台

### 2.4 本地化原则

所有对标复刻都要做中国化改造：

1. 文案更口语化，减少英文训练术语
2. 训练建议更保守，符合中国新手跑者普遍基础
3. 信息密度适配微信小程序，而不是原生 App 的复杂深页面
4. 通知与召回依赖订阅消息、收藏、最近使用和首页回访，而不是系统级推送
5. 配速与成绩表达优先使用中文语境下更熟悉的方式

## 4.2 Runna 页面逻辑复刻要求

### 页面 1：首页 / Today

复刻重点：

1. 顶部显示距离比赛时间和当前训练阶段
2. 中部主卡只突出今天这一节训练
3. 主卡内同时出现训练内容、训练目的、注意事项
4. 页面下方保留未来几天或本周预览

本地化改造：

1. 减少信息密度
2. 文案更像中文教练，而不是英文翻译
3. 强化“今天没跑成怎么办”的入口

### 页面 2：计划页 / Calendar

复刻重点：

1. 周视图和月视图切换
2. 卡片式训练日历
3. 拖拽训练到其他日期
4. 调整后即时展示后续变化

本地化改造：

1. 适配小程序手势和滚动行为
2. 重要训练卡片更明显
3. 重排后必须用中文解释“为什么这么改”

### 页面 3：训练详情页 / Workout Detail

复刻重点：

1. 告诉用户做什么
2. 告诉用户为什么做
3. 告诉用户怎么判断做得对不对
4. 告诉用户今天不要做什么

本地化改造：

1. 不出现依赖 GPS 的字段
2. 把“开始跑步”改成“完成后反馈”
3. 把实时执行型能力改成训练前说明和训练后解释

### 页面 4：计划调整页 / Plan Adjustment

复刻重点：

1. 用户跳过训练后，立即给出重排结果
2. 清楚告诉用户“保了什么，删了什么，为什么”
3. 允许用户接受或恢复原安排

本地化改造：

1. 语气更克制
2. 新手优先保长距离与恢复

## 8. 算法实施规则

## 8.1 初始计划生成规则

输入：

1. 赛事类型
2. 比赛日期
3. 当前最长距离
4. 近 4 周频率
5. 近 4 周跑量
6. 每周可训练天数
7. 目标模式
8. 目标成绩

输出：

1. 计划长度
2. 每周结构
3. 每日任务
4. 初始预测成绩

### 规则原则

1. 新手先保连续性，再谈强度
2. 首场赛事默认保守
3. 冲成绩模式也不能破坏恢复节奏
4. 本周只保 1 个关键训练锚点和 1 个耐力锚点

## 8.2 动态重排规则

### 触发条件

1. 用户手动跳过训练
2. 用户把训练拖到新日期
3. 用户反馈偏累或很累
4. 用户反馈没完成
5. 用户反馈不适

### 核心策略

1. 优先保关键训练和耐力训练
2. 非关键训练优先让位
3. 不允许高强度连续堆叠
4. 距离比赛越近，越偏向删课而不是补课
5. 已经错过的训练不自动顺延到无限后面

### 重排窗口

默认只重排未来 7 天。

特殊情况下可重排未来 14 天：

1. 连续漏掉两次关键训练
2. 目标成绩出现明显下调
3. 用户主动触发“重建本周计划”

## 8.3 RPE 与负荷规则

### 基础负荷公式

`sRPE Load = 训练时长（分钟） x RPE`

### 轻量状态指标

1. `fatigue_score`
   基于最近 7 天 sRPE 负荷、主观感受、不适反馈综合计算
2. `fitness_score`
   基于最近 14 天完成率、关键训练完成率和稳定度综合计算
3. `form_score`
   用于表达当前更适合推进、维持还是恢复

### 状态标签

1. `push`
2. `hold`
3. `recover`

## 8.4 配速自适应与成绩预测规则

### 触发输入

1. 最近关键训练完成情况
2. 最近 3 次 RPE
3. 最近 14 天完成率
4. 长距离执行情况
5. 测试跑成绩

### 调整原则

1. 连续 2 次关键训练“明显太轻松”，可小幅上调预测成绩
2. 连续 2 次关键训练“明显过难”，应下调预测成绩或降训练强度
3. 长距离持续缺失时，优先下调信心而不是盲目维持目标
4. 预测变化必须附原因

### 输出

1. 新预测成绩
2. 当前信心
3. 配速建议变化
4. 下阶段重点

## 8.5 每日一句话激励规则

激励文案必须符合：

1. 短
2. 有温度
3. 不喊口号
4. 紧贴当天训练上下文

示例方向：

1. 今天这次轻松跑，不是偷懒，是在给后面的关键训练留空间。
2. 没必要每次都证明自己，把今天稳稳跑完更重要。
3. 你现在最需要的不是更狠一点，而是更稳一点。

## 14. 最终实施结论

这份研发实施版要求研发团队在执行时，明确按下面的顺序推进：

1. 先复刻 Runna 的计划页、首页和动态重排骨架
2. 再补 Trenara 的 RPE 和 7 天调整
3. 再补 Coopah 的解释层和每日激励
4. 最后补 TrainingPeaks 的轻量负荷可视化

如果一句话概括：

> 我们不是做一个中国版 Keep，而是做一个适合中国微信生态的 Runna for beginners。
